01 ภาพรวม & การเปิดใช้

ระบบไม่ได้เก็บข้อมูลเอง — ทุกอย่าง อ่านสดจากชีตต้นทาง ทุกครั้งที่เปิด แก้ที่ชีต แล้วรีเฟรช ระบบจะอัปเดตตาม

ข้อมูลไหลจากไหนบ้าง

แหล่งข้อมูลใช้ทำอะไร
ชีตตารางเวรรายวัน (แท็บตามวันที่)ใครมาทำงาน/หยุด · ทำไฟลท์อะไร · กะ · OT — เป็นหัวใจหลัก
ไฟล์ LL (ติดตามสัมภาระ)กำลังพลฝั่ง LL (ถ้าตั้งค่า LL_FILE_ID)
ไฟล์ท่า / PAS Counter Bridgeจำนวนเคาน์เตอร์ที่ท่าจัดให้แต่ละไฟลท์ + เวลาเปิด-ปิด
ไฟล์รายชื่อพนักงาน (Pax Manpower)ยอดพนักงานทั้งหมด + ค้นทีมต้นสังกัดของคนซัพจากชื่อ

การเปิดใช้งานประจำวัน

  1. เปิด Web App URL (ลงท้าย /exec) — เลือกวันที่ได้ที่แถบสัปดาห์ด้านบน หรือใส่ ?date=YYYY-MM-DD ท้าย URL
  2. ระบบแคชข้อมูล 15 นาที เพื่อความเร็ว — ถ้าเพิ่งแก้ชีต ให้กดปุ่ม 🔄 รีเฟรช (มุมซ้ายล่าง) เพื่อดึงข้อมูลล่าสุด
  3. สลับธีมสว่าง/มืดได้ที่ปุ่มมุมขวาบนของเบราว์เซอร์ (หน้านี้รองรับทั้งสองธีม)

03 หลักการอ่านค่า & SLA

เข้าใจตรรกะเหล่านี้ จะอ่านผลได้ถูกและรู้ว่าทำไมระบบคิดแบบนั้น

SLA — คนที่ต้องมีต่อไฟลท์

แต่ละสายการบินมีเกณฑ์ [SUP, Check-in, Arrival, Gate, รวม] เก็บไว้ในระบบ (75 สาย) และบางสาย แยกตามชนิดเครื่อง (aircraft type) เช่น EY:

EY · ชนิดเครื่องCheck-in ที่ต้องการ
B787-96
B787-107
A321Neo5

ระบบเลือกเกณฑ์จากแถว “A/C TYPE - CFG” ในบล็อกไฟลท์ — ถ้าไม่ระบุ จะใช้ค่ามาตรฐาน (ลำใหญ่สุด)

เพดานเคาน์เตอร์ (Counter cap)

ทำไมบางไฟลท์ไม่ขึ้นเตือน “SLA ไม่ครบ” ทั้งที่คนน้อยกว่า SLA

ถ้าท่า “ตัดเคาน์เตอร์” ให้น้อยกว่าที่ SLA ต้องการ (เช่น SLA ขอเช็คอิน 6 แต่ท่าให้ 5) ระบบจะ ลดเพดานเช็คอินลงเท่าจำนวนเคาน์เตอร์จริง — ส่งคนได้เท่าที่มีเคาน์เตอร์ ไม่เตือนเกินจริง (ดึงจากไฟล์ท่า/Bridge)

ช่วงเวลา “ครอบคลุมไฟลท์” (coverage window)

ระบบคิดว่าคนหนึ่ง “คุมไฟลท์” ตั้งแต่ เวลาบรีฟ (ก่อนเปิดเคาน์เตอร์) จนถึง STD + งานหลังไฟลท์ (post) — ค่าต่างกันรายสาย เช่น

  • บ้าน EY: ทุกตำแหน่ง (WEL GUEST / ACA / ARR / BINGO / SUP) ทำช่วงเดียวกัน = เปิดเคาน์เตอร์ − 1 ชม.บรีฟ ถึง STD + 45 นาที (เคลียร์หลังไฟท์)
  • งาน “NO GATE” = ทำเช็คอินอย่างเดียว ระบบจะไม่คิดครอบคลุมถึงเกท/post-flight

การซัพพอร์ตข้ามทีม

บางสายรับคนช่วยจากทีมอื่นได้เฉพาะบางตำแหน่ง (เช่น รับเฉพาะ Gate) บางสายไม่รับเลย — ระบบใช้กติกานี้ตอนแนะนำคนในแท็บ Support และไม่แนะนำคน OT-off / คนออฟ ก่อนคนกะปกติ

04 วิธีกรอกชีตให้ระบบอ่านถูก

ปัญหาส่วนใหญ่มาจากการกรอก — ทำตามแนวทางนี้ ระบบจะอ่านตรงและ warning จะลดลง

กรณีกรอกแบบนี้ผล
คนมาช่วยจากทีมอื่น (ซัพพอร์ต)สมชาย PVT หรือ สมชาย (PVT)ระบบรู้ทีมต้นสังกัด
ซัพแต่ลืมใส่รหัสทีมใส่ชื่อให้ตรง master (ไทย/อังกฤษ)ระบบ ค้นทีมจากชื่อให้อัตโนมัติ (ป้าย ·จากรายชื่อ)
ทำเช็คอินอย่างเดียว ไม่ไปเกทเขียน NO GATE ต่อท้ายงานไม่คิดครอบคลุมเกท/post
ระบุชนิดเครื่องเพื่อ SLA ที่ถูกแถว A/C TYPE - CFG เช่น B787-9เลือก SLA ตามลำ
เวลา / ช่วงเวลา0925, 0925/1055, -1405/1445อ่านเป็น 09:25 / ช่วง
คนหยุดOFF หรือ X ในช่องกะ/เวลานับเป็นหยุด
มา OT วันหยุดกรอก ชั่วโมง OT + ช่วงเวลานับเป็นมา OT (ไม่ใช่หยุด)
⚠️ ระวังบ่อย

เขียน OFF/X แต่ยังจัดคนลงไฟลท์ → ระบบนับเป็น “ไม่มาทำงาน” ทั้งที่นั่งไฟลท์อยู่ ทำให้ยอด/ครอบคลุมเพี้ยน · ถ้ามาทำงานให้แก้เป็น Onduty ถ้ามาช่วย OT ให้กรอกชั่วโมง OT

05 การตั้งค่า (สำหรับแอดมิน)

ส่วนนี้ทำครั้งเดียว/นานๆ ครั้ง — ปกติผู้ใช้ทั่วไปไม่ต้องยุ่ง

PAS Counter Bridge (ข้อมูลเคาน์เตอร์ ±7 วัน)

ไฟล์ท่าแชร์ตรงไม่ได้ จึงใช้ไฟล์ Bridge ตัวกลาง IMPORTRANGE ข้อมูลเข้ามาเอง — วางสูตรนี้ที่ A1 ของแท็บชื่อ COUNTER (ดึงวันนี้ ±7 วัน เลื่อนวันอัตโนมัติ ไม่ต้องสร้างแท็บเพิ่ม):

=LET(
 src,"<ID ไฟล์ COUNTER CHECK ของท่า>",
 blk,LAMBDA(off,LET(
   d,TODAY()+off,
   mo,CHOOSE(MONTH(d),"JAN","FEB","MAR","APR","MAY","JUN","JUL","AUG","SEP","OCT","NOV","DEC"),
   t,DAY(d)&mo&RIGHT(YEAR(d),2),
   ts,DAY(d)&" "&mo&RIGHT(YEAR(d),2),
   raw,IFERROR(IMPORTRANGE(src,t&"!A4:F"),IMPORTRANGE(src,ts&"!A4:F")),
   IFERROR(HSTACK(raw,IF(CHOOSECOLS(raw,2)="","",
     TEXT(DAY(d),"00")&"."&TEXT(MONTH(d),"00")&"."&YEAR(d))),{"","","","","","",""})
 )),
 VSTACK({"AIRLINE","FLIGHT","STD","OPEN-CLOSE TIME","NO. OF COUNTERS","COUNTER NO.","DATE"},
   blk(-7),blk(-6),blk(-5),blk(-4),blk(-3),blk(-2),blk(-1),blk(0),
   blk(1),blk(2),blk(3),blk(4),blk(5),blk(6),blk(7)))
  • ครั้งแรกจะขึ้น “Allow access” — กดอนุญาต 1 ครั้ง (ถ้าไม่ขึ้น ให้ทดสอบด้วย =IMPORTRANGE(src,"9JUL26!A1:F5") ในเซลล์ว่างก่อน)
  • ระบบอ่านคอลัมน์ NO. OF COUNTERS + DATE เอง และกรองตามวันที่ที่เปิดดู
  • ตั้ง COUNTER_FILE_ID ในโค้ดให้ชี้ไฟล์ Bridge นี้

ไฟล์รายชื่อพนักงาน (ค้นทีมอัตโนมัติ + ยอดรวม)

  • ตั้ง MASTER_FILE_ID_RB = ไฟล์ Pax Manpower (ต้องมีชีต Total)
  • บัญชีที่รัน Apps Script ต้องมีสิทธิ์ เปิดดูไฟล์นี้ — ทดสอบด้วยฟังก์ชัน debugDumpMaster

อัปเดตโค้ด (deploy)

  1. clasp: git pull → clasp push (push ไฟล์ย่อย .gs — Code.gs ถูก ignore) — อย่าให้มีทั้ง Code.gs รวม + ไฟล์ย่อยพร้อมกัน
  2. หรือวางมือ: คัดลอก Code.gs ทั้งไฟล์ วางทับใน editor (ไฟล์เดียว)
  3. เสร็จแล้ว: Deploy → Manage deployments → New version เพื่อให้ /exec รันของใหม่ → เปิดเว็บกด 🔄
หมายเหตุ build

โปรเจกต์เขียนเป็นไฟล์ย่อย (.gs) แล้วรวมเป็น Code.gs ด้วย python3 build_code.py — แก้ที่ไฟล์ย่อยเสมอ ไม่แก้ Code.gs ตรงๆ

อาการวิธีแก้

ตรวจข้อมูล ขึ้น “ซัพพอร์ตไม่ระบุทีม”ใส่ ชื่อ + รหัสทีม หรือ (รหัส) ท้ายชื่อ · หรือเช็คว่าชื่อสะกดตรงกับไฟล์รายชื่อ (ระบบจะค้นทีมให้เอง)
“มาทำงาน/มีไฟลท์ แต่อ่านเวลากะไม่ได้”กรอกเวลากะ (เช่น 08:00-17:00) หรือช่วง OT ให้อ่านได้

Bridge ขึ้น #REF!ยังไม่กด Allow access — ทดสอบด้วยสูตร IMPORTRANGE ง่ายๆ ก่อน แล้วกดอนุญาต
Bridge ขึ้น #N/A (ชื่อแท็บไม่ตรง)เกิดจาก locale ไทย (เดือน/ปี พ.ศ.) — สูตรในคู่มือใช้ DAY/MONTH/CHOOSE/YEAR แก้ให้แล้ว
ค้นทีมจากไฟล์รายชื่อไม่ทำงานเช็ค 3 อย่าง: deploy โค้ดใหม่แล้ว? · บัญชีเข้าไฟล์ได้? (debugDumpMaster) · กด 🔄 แล้ว?
หลักคิดเวลาเจอผลแปลก

ระบบอ่านสดจากชีตเสมอ — ผลที่เห็นสะท้อน “สิ่งที่กรอกในชีต” เกือบทั้งหมด ถ้าผลผิด ให้เริ่มจากดูแท็บ ตรวจข้อมูล ก่อน แล้วไปแก้ที่ต้นทาง จะแก้ได้ตรงจุดกว่าการไปแก้สรุปทีหลัง
