## 1) ระบบนี้คืออะไร
```
ไฟล์ assignment รายวัน (Google Sheet, 1 แท็บ/ทีม)
            │  อ่าน + แปลง (RosterReader)
            ▼
   จัดกลุ่ม / นับกำลังพล / เทียบ SLA / หาคนช่วย
            ▼
        เว็บแดชบอร์ด (หลายแท็บ)  ←  เปิดผ่านลิงก์ .../exec
```
เปิดด้วยลิงก์ Web App (`script.google.com/.../exec`) · เลือกวันที่ได้ · รองรับมือถือ

## 2) ข้อมูลมาจากไหน
- **1 แท็บ = 1 ทีม** — EY, SQ, EK, TR, PG, QR, KE, CHN, SU, TK, AK, CHARTER, WYWK …
- **ทีมพิเศษ** — `PVTLP` (ทีมลอย/สแตนด์บาย), `PORTER`, `REV.01 PORTER CREWSIGN`, `ADMIN DOC`
- แต่ละแถว = พนักงาน 1 คน · คอลัมน์มาตรฐาน:

| คอลัมน์ | ความหมาย |
|---|---|
| **ID** | รหัสพนักงาน |
| **Position** | ตำแหน่ง (Sup / Snr / Agent / Admin / Porter / Crew Sign) |
| **NAME** | ชื่อ |
| **SHIFT** | รหัสกะ (เช่น H12, E8, G9) |
| **TIME (IN/OUT)** | เวลาเข้า-ออกกะจริง |
| **Re-Sked** | เวลาที่ถูกเปลี่ยน/เรียกเข้าใหม่ |
| **OT (IN/OUT)** | ช่วง OT (ก่อน/หลังกะ) |
| **REMARK / STATUS** | สถานะ: `Onduty` / `Off` / `OT OFF` / `VAC` / `SL` … |
| **FLIGHT / Job** | ไฟลท์+งานที่รับผิดชอบ |

> ⚠️ บางชีต (เช่น PVTLP) ใช้หัวคอลัมน์สถานะชื่อ **`STATUS`** แทน `REMARK` — ระบบอ่านทั้งสองแบบ

## 3) แท็บต่าง ๆ + วิธีอ่าน

| แท็บ | อ่านว่าอะไร |
|---|---|
| **▦ Dashboard** | ภาพรวม: Total / มาทำงาน / หยุด / OT · แยกราย **ทีม** และ **ตำแหน่ง** |
| **🕓 Timetable** | รายคน: กะเข้า-ออก · OT · ไฟลท์ที่รับผิดชอบ (ค้นหาชื่อได้) |
| **✈️ Flights & SLA** | ราย **ไฟลท์**: จัดจริง vs SLA ต้องการ (SUP/Check-in/Gate/Arrival) → ✅ ครบ / ⚠️ ขาด |
| **🆘 ไฟลท์คนไม่ครบ** | ไฟลท์ที่ขาด + **แนะคนมาช่วย** (ข้ามทีม) — ดูวิธีอ่านข้อ 4 |
| **📅 จัดล่วงหน้า** | จัดเวรอัตโนมัติลงเคาน์เตอร์/เกท + export 1 แท็บ/ทีม |
| **🔧 ตรวจ Assign** | ตรวจความเหมาะสมของการจัด (OT เกิน · ช่วงว่าง · ครอบคลุมไฟลท์) |
| **OT Dashboard** | สรุปชั่วโมง OT สะสมรายทีม |

## 4) วิธีอ่านแท็บ 🆘 "ไฟลท์คนไม่ครบ" ทีละช่อง

### โครงคอลัมน์
```
Flight │ สายการบิน │ ระบบเช็คอิน │ ทีม │ STD │ ตำแหน่งที่ขาด │ ช่วงเวลา │ เลือกคนมาช่วย
```

| ช่อง | อ่านว่าอะไร |
|---|---|
| **Flight** | เลขไฟลท์ (เช่น `WY833/834`) |
| **สายการบิน** | รหัสสาย → ใช้เปิดเกณฑ์ SLA |
| **ระบบเช็คอิน** | ระบบที่ต้องใช้ (Sabre/Altea/Gonow/AS Connect…) → **คนช่วยเช็คอินต้องรู้ระบบนี้** |
| **ทีม** | ทีมเจ้าของไฟลท์ |
| **STD** | เวลาเครื่องออก |
| **ตำแหน่งที่ขาด** | เช่น `Check-in ขาด 3 (Sabre)` · `Gate ขาด 2` · `Arrival ขาด 1` · `SUP ขาด 1` |
| **ช่วงเวลา** | ช่วงที่ต้องการคน (เช่น `06:10-08:10`) — คนช่วยต้องว่างครอบช่วงนี้ |
| **เลือกคนมาช่วย** | รายชื่อที่ระบบแนะ (เรียงดีสุดก่อน) |

### ป้าย "คนช่วย" แต่ละชิป
```
KRITTITEE · Agent · H12 08:00-20:00 · 0 ไฟลท์
   ชื่อ      ตำแหน่ง     กะ/เวลาทำงาน      งานที่ติดอยู่
```
| ส่วน | ความหมาย |
|---|---|
| **กะ** | `H12 08:00-20:00` = ทำงานจริงช่วงนี้ · `OFF · re-sked 08:00-20:00` = คนหยุด เรียกมาช่วยได้ตามกะเดิม |
| **X ไฟลท์** | ติดอยู่กี่ไฟลท์แล้ว → **`0 ไฟลท์` = ว่างสุด เลือกก่อน** |

### ลำดับการแนะ (ตามที่ Duty ทำจริง)
1. **ทีมลอย (PVTLP/STBY) ก่อน**
2. คนทำงาน (Agent → Snr → Sup) ที่ว่าง
3. คนหยุด (`re-sked`) — ทางเลือกสุดท้าย (ตามช่วงกะของเขา ไม่ใช่ว่าง 24 ชม.)

### สัญญาณพิเศษ
- **`ไม่มีคนว่างที่รู้ระบบ AS Connect`** = ไม่มีใครช่วยได้เลย → ต้องเรียก OT/ข้ามวัน

## 5) แนวคิดหลักที่ต้องเข้าใจ

### 🟢 สถานะคน (bucket) — อ่านจาก REMARK/STATUS + SHIFT + OT
| สถานะ | ความหมาย | นับเป็น "มาทำงาน"? |
|---|---|:--:|
| **working** | มากะปกติ (Onduty) | ✅ |
| **ot_off** | วันหยุด **มาทำ OT จริง (มีชั่วโมง OT)** | ✅ |
| **off** | หยุด · รวม "OT OFF" ที่ยังไม่มีชั่วโมง OT | ❌ |
| **sick / vac / leave** | ป่วย / พักร้อน / ลา | ❌ |

> **on-duty = working + ot_off**
> "OT OFF" ที่ยังไม่ลงชั่วโมง OT = ถือว่า **หยุด** (ยังไม่ได้มาทำ)

### ✈️ SLA (เกณฑ์คนต่อไฟลท์)
แต่ละสายกำหนดคนต่อ **เฟส**: **SUP** (หัวหน้า/Flight Controller) · **Check-in** · **Gate** · **Arrival**
- เทียบ "จัดจริง vs ต้องการ" → ขาดกี่คน เฟสไหน
- **ตัดตามขา:** ขาออกอย่างเดียว → ไม่นับ Arrival · ขาเข้าอย่างเดียว → ไม่นับ Check-in/Gate

### 🆘 Support Finder (หาคนช่วย — อิงวิธี Duty)
กรองคนข้ามทีมที่: **ว่างในช่วงเวลานั้นจริง** + **รู้ระบบเช็คอิน** + ไม่ติดไฟลท์อื่น → เรียงทีมลอยก่อน

### ⏱️ คำที่เจอบ่อย
- **STA / STD** = เครื่องถึง / ออก
- **re-sked** = เปลี่ยนเวลา/เรียกเข้าเวรใหม่ (คนหยุดมาช่วยตามกะของเขา)
- **Common check-in** = SU/SQ ใช้เคาน์เตอร์รวมหมุนเวียน (ไม่ผูกไฟลท์เดียว)
- **iPort** = ระบบที่ใครก็ช่วยเช็คอินได้ (ไม่ต้องเช็คว่ารู้ระบบ)

> ตารางเต็ม (70+ สาย) อยู่ในตัวแปร `SLA_RQ` (ไฟล์ `SLA.gs`)

### เวลาช่วง (window) แต่ละเฟส
| เฟส | ช่วงเวลา |
|---|---|
| **Check-in** | เปิด-ปิดเคาน์เตอร์ (ก่อน STD ตาม offset รายสาย `SLA_DB`) |
| **Gate** | STA−30 → STD (+post) |
| **Arrival** | STA−30 → STD (+post) |
| **SUP** | ตั้งแต่เปิดเช็คอิน → จบไฟลท์ |

> post-flight: full-service 30 นาที / LCC 20 นาที

## 7) วิธีใช้งานประจำวัน
1. เปิดเว็บ → เลือก **วันที่** บนแถบบน
2. ดู **Dashboard** ว่ากำลังพลพอไหม → **🆘** ดูไฟลท์ขาด + คนช่วย
3. แก้ไฟล์ assignment แล้ว → กด **🔄 รีเฟรช** ให้ดึงใหม่ (ระบบ cache ~3 นาทีเพื่อความเร็ว)
4. **📅 จัดล่วงหน้า** → กดจัดเวร → export ส่งทีม

## 8) ตัวเลขเพี้ยน — เช็คอะไรก่อน
| อาการ | สาเหตุที่พบบ่อย |
|---|---|
| คนทีมหนึ่ง "มาทำงาน" เยอะผิดปกติ | คอลัมน์สถานะใช้หัวชื่อแปลก (เช่น `STATUS`) หรือ "OT OFF" ไม่มีชั่วโมง OT |
| ทีมพิเศษนับผิด (Crewsign/Admin Doc/Porter) | ไฟล์เปลี่ยนฟอร์ม → ใช้ parser มาตรฐานแล้ว |
| ไฟลท์ถูกจัดคนซ้ำ | เลขไฟลท์เขียน 2 แถว (เช่น `EK396/397` กับ `EK397`) |
| เห็นข้อมูลเก่า | ลืมกด **🔄** หลังแก้ไฟล์ |

> ตรวจ offline ได้ด้วย: `python3 reference_parser.py <ไฟล์.xlsx> [TEAM]`

## 9) โครงสร้างโค้ด (สำหรับดูแล)
| ไฟล์ (module) | หน้าที่ |
|---|---|
| `RosterReader.gs` | อ่าน/แปลงไฟล์ assignment → records (**parser หลักอยู่นี่**) |
| `SLA.gs` | เกณฑ์ SLA (`SLA_RQ`, `SLA_DB`) + Support Finder |
| `AssignCheck.gs` | ตรวจความเหมาะสมการจัด |
| `AutoPlan.gs` / `AdvancePlan.gs` | จัดเวรอัตโนมัติ / จัดล่วงหน้า |
| `OTDashboard.gs` | สรุป OT |
| `WebDashboard.gs` | หน้าเว็บ + ดีไซน์ + โลโก้ |
| `RosterBot.gs` | งานเบื้องหลัง (อ่านไฟล์ Drive + แจ้ง Chat) |
| `reference_parser.py` | ตัว validate offline (มิเรอร์ logic เดียวกับ .gs) |
| `Code.gs` | **bundle รวมมือ** — `.claspignore` ตัดออก (clasp ไม่ push) |

> ⚠️ **แก้โค้ดต้องแก้ที่ module จริง** แล้วรัน `python3 build_code.py` (Code.gs เป็นแค่ก้อนรวมไว้ก็อปลง Apps Script editor — แก้ที่ Code.gs อย่างเดียวจะไม่ deploy)

### การจัดกลุ่มตำแหน่ง (position group)

ไม่งั้นดูตำแหน่ง: SUP/PSS → PSS · SNR → SNR · ที่เหลือ → PSA
