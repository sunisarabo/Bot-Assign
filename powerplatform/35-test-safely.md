# 35 · ทดลองใช้แอปโดยไม่กระทบข้อมูลจริง

หลัก: **อย่าให้แอปทดสอบเขียนลงตาราง/ลิสต์จริง** · แยก "ที่เก็บข้อมูล" ของการทดสอบออกมา

## ทางเลือก (เรียงจากปลอดภัย→เบา)

### 1) 🟢 Sandbox environment แยก (ปลอดภัยสุด — แนะนำถ้ามีสิทธิ์)
admin.powerplatform.microsoft.com → **+ New environment** (ชนิด **Sandbox**)
- **Copy environment** (จาก Production → Sandbox) = โคลนแอป + ตาราง + ข้อมูล มาทั้งชุด → ทดสอบอิสระ ลบทิ้งได้
- หรือสร้าง env เปล่า แล้ว **import solution** ของแอป + ใส่ข้อมูลตัวอย่าง
- ผู้ทดสอบเปิดแอปใน Sandbox → เขียนอะไรก็ **ไม่แตะ Production**
- พอโอเค → export solution จาก Sandbox → import ทับ Production (ครั้งเดียว)
> ต้องมี capacity/สิทธิ์สร้าง env (เช็ก IT)

### 2) 🟡 สำเนาแอป + สำเนาที่เก็บข้อมูล (ไม่ต้องสร้าง env)
ทำใน environment เดิม แต่ชี้ไป "ข้อมูลสำเนา":
- **SharePoint list:** สร้างลิสต์ชุดทดสอบ `PAS_Porter_TEST` / `PAS_Assignment_TEST` / `PAS_Duty_TEST` / `PAS_Users_TEST` (คัดลอกโครง + ใส่ข้อมูลตัวอย่างบางส่วน)
- **Dataverse:** โคลนตารางเป็น `..._test` หรือ import ข้อมูลตัวอย่าง
- **Save As** แอปเป็น `PAS (TEST)` → แก้ **Data sources** ให้ชี้ลิสต์/ตาราง `_TEST`
- แชร์ `PAS (TEST)` ให้คนทดสอบ → เขียนลง `_TEST` เท่านั้น · ของจริงไม่กระทบ
> ข้อดี: ไม่ต้องมีสิทธิ์สร้าง env · ข้อเสีย: ต้องดูแล 2 ชุด data source ชั่วคราว

### 3) 🟡 ทดสอบด้วย "วันในอนาคต" + บัญชีทดสอบ (เบาสุด แต่ยังเขียนตารางจริง)
ถ้าไม่สะดวกทำสำเนา — ทดสอบบน data จริงแบบจำกัดวง:
- ใช้ **วันทดสอบไกล ๆ** (เช่น 2099-01-01) → `day_key = "2099-01-01"` ไม่ชนงานจริงวันนี้ · views จริงกรองตามวันนี้อยู่แล้วจึงไม่โผล่
- สร้าง **พนักงาน/พอตเตอร์ทดสอบ** (emp_code ขึ้นต้น `TEST`) + บัญชี Kiosk ทดสอบ → กรองออกจากรายงานจริงด้วย `!StartsWith(emp_code,"TEST")`
- เคส walk-in ทดสอบใช้ `job_no` 9xxx ของวัน 2099 → ลบทิ้งง่าย
> ⚠️ ยัง **เขียนตารางจริง** — เสี่ยงถ้าเผลอใช้วันจริง/ลืมลบ · เหมาะทดสอบปุ่ม/สูตรเร็ว ๆ ไม่เหมาะทดสอบกับทีมหลายคน

## แนะนำสำหรับเคสนี้
- อยากให้ทีมลองหลายคน/หลายวัน → **ข้อ 1 (Sandbox)** หรือ **ข้อ 2 (สำเนา + Save As)**
- แค่เช็กหน้า/ปุ่มเองเร็ว ๆ → **ข้อ 3 (วัน 2099 + TEST)** พอ แล้วลบแถวทดสอบทิ้ง

## เช็กลิสต์ก่อนปล่อยทดสอบ
- [ ] แอปทดสอบชี้ **data source สำเนา** (ไม่ใช่ของจริง) — เปิด Data sources ดูชื่อลิสต์/ตารางให้แน่
- [ ] flow/plug-in ที่เขียนข้อมูล (เช่น WC rules, build-cases) ชี้ **ที่เก็บทดสอบ** ด้วย (ไม่งั้น flow จริงยังยิงลงของจริง)
- [ ] ปิด/แยก **การแจ้งเตือน** (LINE/เมล) ของเวอร์ชันทดสอบ ไม่ให้ยิงหาคนจริง
- [ ] ข้อมูลตัวอย่างใช้ชื่อ/รหัส **ทดสอบ** ไม่ปนคนจริง (PDPA)
- [ ] ทดสอบเสร็จ → ลบ env/ลิสต์ทดสอบ หรือแถว `TEST`/วัน 2099 ทิ้ง

## ขึ้น Production อย่างปลอดภัย
- แก้/เพิ่มทีละหน้าในแอปจริง + **Save version** (Power Apps เก็บเวอร์ชัน → Restore ย้อนได้)
- เปลี่ยนที่กระทบข้อมูล (คอลัมน์ใหม่/flow) ให้ทำนอกเวลาพีค + มี backup (env auto-backup)
- ค่อย ๆ เปิดให้บางทีมก่อน (pilot) แล้วขยาย
