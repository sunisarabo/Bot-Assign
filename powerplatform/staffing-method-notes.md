# วิธีจัดพนักงาน (จากไฟล์วิเคราะห์ JAN–OCT 69) → เอามาใช้กับระบบยังไง

ไฟล์ "วิเคราะห์รูปแบบการจัดพนักงาน PAS-HKT" (ม.ค. เทียบ ต.ค. 69) ให้ **วิธีคิด + ตัวเลขจริง** ที่ใช้แทนค่าประมาณในระบบได้

## วิธีที่เขาใช้ (สรุป)
1. **Demand รายชั่วโมง (P80)** = จำนวนคนติดงานไฟลท์ต่อชั่วโมง ณ "วันหนักระดับ 80%" (ไม่ใช่พีคสุด = ไม่เผื่อเกิน)
2. **+ Buffer 10%** (ลา/พัก/งานนอกไฟลท์) → "ต้องการรวม buffer" ต่อชั่วโมง
3. **จัดกะ (Integer Programming, ≤6 แบบกะ)** → หา **เวลาเริ่มกะ + ความยาว + จำนวนคน** ที่คลุม demand ด้วยคนน้อยสุด · ช่องติดลบ = ต้อง OT/Pool
4. **ขนาดทีม = คนต่อวัน ÷ 0.65** (อัตราทำงานจริง/พนักงานทั้งหมด ≈ ทำงาน 4–5 วัน/สัปดาห์ + ลา)
5. **คนมาตรฐานต่อไฟลท์ = มัธยฐาน (ปัดขึ้น)** จากที่จัดจริง + แยกสัดส่วน (Supervisor/Control/FC/…)

## ตัวเลขสำคัญที่ได้
- **อัตราทำงานจริง 0.65** · **Buffer 10%** → ใช้แปลง "คน/วัน" ↔ "ขนาดทีม"
- OT ลดจาก ~1,184 → ~627 ชม./วัน (รับคนใหม่ B26xxxxx แทน OT) — แต่ ต.ค. บางทีม OT ยังไม่กรอก (TR/SU=0) ต้องตรวจ
- ทีมที่คนว่างจากไฟลท์กลางวันมาก: **PVT 4% · CHARTER 12% · WK/SV 33% · KE 42%** → ดึงไปซัพ/อบรม/เอกสาร

## เอามาใช้กับระบบที่สร้าง (4 จุด)
| ใช้ทำอะไร | จากชีต | เสียบเข้า |
|---|---|---|
| **1. manning จริงต่อไฟลท์** (แทน SLA_RQ) | `มาตรฐานไฟลท์` ("คนมาตรฐานแนะนำ") | `tools/build_int_roster.py` → MANNING/สูตรตำแหน่ง · sizing แม่นขึ้น |
| **2. เวลาเริ่มกะจริงต่อทีม** (แทน 3 bands M/A/N) | `Template กะ` / `รูปแบบกะ` | `BANDS` + shift code ใน generator + `SHIFT_TIME` ใน roster → กะตรงกับที่จัดจริง |
| **3. ขนาดทีมที่ควรมี** (เช็ก under/over-staff) | 0.65 + buffer 10% | KPI: ต้องการ/วัน ÷ 0.65 เทียบจำนวนคนในทีม → ธงขาด/เกิน |
| **4. Pool ซัพข้ามทีม** (คนว่างกลางวัน) | สัดส่วนงานผูกไฟลท์ต่ำ (PVT/CHARTER/WK-SV/KE) | หน้า Support/เติมคน: เสนอดึงจากทีมที่ว่างช่วงนั้น |

## ข้อเสนอลำดับทำ (impact สูง→)
- **A. Demand รายชั่วโมง → sizing แทน 3 bands** — generator คิด demand/ชม. จาก flight_work_intervals (มีอยู่แล้ว) แล้วออก "เวลาเริ่มกะ" แบบ Template (greedy/IP) → roster ใช้กะจริง ไม่ใช่ M/A/N ตายตัว
- **B. ดึง "มาตรฐานไฟลท์" → ตาราง manning จริง** ป้อน generator (ต่อทีม/ต่อไฟลท์) → เลข sizing/ชิพตรงจริง
- **C. KPI ขนาดทีม (÷0.65)** ในหน้า Roster/MANPOWER → บอกทีมไหนคนไม่พอ/เกิน
- **D. Pool ซัพกลางวัน** — ต่อยอดหน้า Support/เติมคน

> ทั้งหมด "เสริมความแม่น" ของ sizing/roster ที่ทำไว้ — โครงเดิม (4-หยุด-2 + OT ladder + 3 มุมมอง) ไม่ต้องรื้อ
