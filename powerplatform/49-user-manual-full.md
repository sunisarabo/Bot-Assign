# 49 · คู่มือการใช้งานระบบ PAS (ฉบับเต็ม — "ต้องรู้ระบบ")

ระบบ **PAS · Passenger Services Manpower System** (PSA · ท่าอากาศยานภูเก็ต)
คู่มือนี้สำหรับ **ทั้งผู้ใช้งาน (พนักงาน/พอตเตอร์/หัวหน้า) และทีมซัพพอร์ต/ผู้ดูแลระบบ** — อ่านจบแล้วต้องเข้าใจว่าระบบทำงานยังไง แต่ละหน้าทำอะไร และแก้ปัญหาที่พบบ่อยได้

> บทที่ 1 (การเข้าสู่ระบบ) อยู่ในไฟล์ `43-user-manual-login.md` แยกต่างหาก · ไฟล์นี้คือบทที่ 0 + 2–6 + สิทธิ์ + แก้ปัญหา

## บทที่ 2 · งานของฉัน + รับทราบ (scrMe)

**ใครใช้:** พนักงานทุกคน (รวมพอตเตอร์) · **เข้าโดย:** เลือกชื่อ + PIN ที่ scrSignIn (ดูบท 1) หรือ M365

### หน้าตา
- หัวข้อ: ชื่อคุณ · วันที่วันนี้
- **2 แท็บ:** `งานไฟลท์ (n)` และ `♿ งานวีลแชร์ (n)` — ตัวเลขคือจำนวนงานวันนี้
- **แถบเตือน:** `⚠ ยังไม่รับทราบ n งาน — กดรับทราบก่อนเริ่มงาน` (แดง) หรือ `รับทราบครบแล้ว ✓` (เขียว)

### สิ่งที่ทำได้
1. **ดูงานของตัวเองวันนี้** — การ์ดเรียงตามเวลา STA: ชื่อไฟลท์ · หน้าที่ · STA–STD (สีต่างตามประเภทงาน เช่น วีลแชร์/ซัพพอร์ต)
2. **กดรับทราบ** (สำคัญ/บังคับ) — กดปุ่ม **"กดรับทราบ"** ที่งานแต่ละชิ้น **ก่อนเริ่มงานจริง** → ระบบบันทึกเวลา (`acknowledged=true, ack_at`) · กดแล้วการ์ดเปลี่ยนเป็น `✓ รับทราบแล้ว`
3. **แท็บวีลแชร์** — การ์ด `🦽 {ไฟลท์} · เกท {gate} · {สถานะ}` + รถเข็นที่ได้รับมอบหมาย · ปุ่ม **"รับเคส/รับทราบ"** (ถ้ามีรถเข็นจ่ายให้แล้ว การกดจะ **เริ่มเที่ยวงานทันที** และสถานะเป็น ON_PROCESS)

### กฎที่ต้องรู้
- **ย้อนดูงานเก่าได้ไม่จำกัด · ดูล่วงหน้าได้แค่พรุ่งนี้** (วันถัดไปไกลกว่านั้นถูกล็อก 🔒)
- สถานะวันในภาษาไทย: ขึ้นงาน · OT (วันหยุด) · วันหยุด (OFF) · ลาป่วย · ลาพักร้อน · ลา · อบรม
- KPI ของตัวเอง: ชม.กะ · ชม.OT · utilization %
- งานว่าง → "— วันนี้ยังไม่มีงานไฟลท์ของคุณ —"

## บทที่ 3 · ตารางเวร / แลกเวร / ลา (scrRoster)

**ใครใช้:** ดูได้ทุกคน · **แก้ได้เฉพาะหัวหน้า/แอดมิน** (`varPriv`)

### ดูตารางเวร (กริด คน × วัน)
- เลือก **ทีม + เดือน** แล้วโหลด → กริดจาก `PAS_Duty`
- ช่องแสดงรหัสกะ **M / A / N** (หรือ **OFF**) · มี **`*`** ต่อท้าย = วันนั้นมี OT
- สี: M=เหลือง · A=น้ำเงิน · N=ม่วง · OFF=เทา
- แถบสรุปล่างต่อวัน: `M n · A n · N n · OFF n · OT n`
- **พนักงานทั่วไปดูอย่างเดียว** (พนักงานใช้หน้า "งานของฉัน" บทที่ 2 แทน)

### เปลี่ยนกะ (หัวหน้า)
แตะช่อง → ป๊อปอัป → เลือก M/A/N/OFF → บันทึก

### แลกเวร (โหมดแลกเวร)
1. เปิด **"โหมดแลกเวร"**
2. **แตะ 2 ช่อง** ที่จะสลับกัน (สลับได้ทั้งกะต่างกันและ OFF↔ทำงาน)
3. **โควตา 3 ครั้ง/คน/เดือน** — เกินขึ้น "เกินโควตาแลกเวร 3 ครั้ง/เดือน" · 1 ครั้งนับทั้ง 2 คน · มี log (`pas_swap_log`) · แสดง "แลก n/3" ต่อคน

### ลา (Leave)
แตะช่อง (ไม่ได้อยู่ในโหมดแลกเวร) → เลือกชนิดลา → บันทึก (หัวหน้ากด = อนุมัติทันที, log `pas_leave_request`)

| รหัส | ชนิด | โควตา/กติกา |
|---|---|---|
| **SL** | ลาป่วย | ≤30 วัน/ปี · ลา ≥3 วันติดต้องมีใบรับรองแพทย์ |
| **VL** | พักร้อน | 6/8/10 วัน (อายุงาน ≥1/≥3/≥7 ปี) · ติดกัน ≤5 วัน · ยื่นล่วงหน้า ≥3 วัน |
| **BL** | ลากิจ | 5 วัน/ปี · ติดกัน ≤2 วัน |
| **ML** | ลาคลอด | ≤120 วัน |
| **PL** | ลาอื่น ๆ | ตามเคส |

> โควตาเป็น **คำเตือน ไม่บล็อก** — หัวหน้าตัดสินใจ override ได้ · แสดงคงเหลือต่อคน "SL n/30 · VL n · BL n/5"

## บทที่ 4 · มอบหมายงาน + ไฟลท์ + OT (หัวหน้า/แอดมิน)

### 4.1 มอบหมายงาน (scrAssign)
**ใครใช้:** หัวหน้า/แอดมิน (`varPriv`) · ดูได้ทุกคน

- เลือก **วัน (+ทีม)** → ลงคนใน **ชิพตำแหน่ง** ต่อไฟลท์ (เช่น FC/FR/GA/GC/SOD/J/WEB/Y/ARR/AC/CRW) · `GA 3` = GA#1/#2/#3 · ไฮไลต์ไฟลท์ที่ยังลงคนไม่ครบ
- **3 มุมมอง:** ▦ รายคน · ✈ รายไฟลท์ · 👥 **รายทีม (MANPOWER)** (ทั้งหมด/ตามตาราง/ลาแต่ละชนิด/อบรม/**ทำงานจริง**)
- **ขึ้นกับ roster:** คนจะเลือกได้เฉพาะที่วันนั้นเป็น **WORKING/OT_OFF** · กริดโชว์กะ + เวลาเข้า-ออกตามแผน
- **ชิพงาน + เวลาจริง + OT:** กรอก **เวลาเข้า-ออกงานจริง** (`duty_in/duty_out`) และ **OT ก่อน/หลัง** (`ot_pre/ot_post`) → ป้อนต่อไป scrWH/ตรวจ OT · OT > 36 ชม./สัปดาห์ เตือน
- ปุ่ม **"งานอื่น (เทรน/อบรม)"** ลงงานที่ไม่ใช่ไฟลท์

> ⚠️ **ถ้าทุกคนขึ้น "Off" = ยังไม่ได้จัด roster วันนั้น** → ไปสั่งจัดตารางก่อน (ข้อ 4.4)

### 4.2 ไฟลท์ (scrFlights) — เฉพาะ "แก้ไขได้"
เลือกวัน (+ทีม) → รายการไฟลท์เรียงตาม STA (สีตามสถานะ)
- **แก้** → แก้เลขไฟลท์/วันที่/สายการบิน/ทิศ/STA-STD/เครื่อง/เกท/remark → สถานะ CHANGED
- **เพิ่ม** → สถานะ ADDED
- **ยกเลิก** → สถานะ CANCELLED + remark (**ไม่ลบแถว** เก็บประวัติ) · งานที่ผูกถูกตีธง "[CANCELLED]" และหลุดจากการมอบหมาย

### 4.3 ชม.ทำงาน/OT + ตรวจ OT (scrWH / scrOT)
- **ชม.ทำงาน:** ต่อคน "ทำงาน n · OT n" + KPI ทีม · เตือนแดงถ้า **OT เกิน 36 ชม./สัปดาห์**
- **ตรวจ OT ขอจริง:** เทียบ **OT จริง** (ดึงจากไฟล์ master ผ่าน flow `GetActualOT`) กับ **OT ตามแผน (roster)** → สถานะ **ตรงแผน / เกินแผน / หลุดแผน** · สรุปต่อทีม (แถวแดง = คนหลุดแผน) + รายชื่อ "ขอจริงแต่ไม่ได้ลง Assign" · ถ้าไฟล์ OT ยังไม่อัปเดตจะขึ้นว่าวันนั้นว่าง

### 4.4 จัดตารางอัตโนมัติ + แก้มือ (generate)
- **Roster "จัดอัตโนมัติ"** → สั่งคิว (`pas_gen_request`, 4-หยุด-2 + หมุนกะ + OT ladder) → "ระบบจะอัปเดตใน ~ไม่กี่นาที"
- **Assign "⚡ จัดอัตโนมัติ"** → ลงคน WORKING เข้าชิพที่ว่างแบบ round-robin (+ "ล้างเฉพาะ AUTO")
- **กฎ source:** auto = `pas_source=AUTO` · แก้มือ = `MANUAL` · จัดใหม่ทับเฉพาะ AUTO → **งานที่แก้มือ/แลกเวร/ลา ไม่หาย**

### 4.5 แดชบอร์ดรายวัน (scrDay) — ดูทุกคน
`◀ วันที่ ▶ รีเฟรช` · การ์ดตัวเลข: คนทำงาน · OT (ชม.) · ไฟลท์ · ลงงานแล้ว · ยังไม่รับทราบ · ตารางต่อทีม (ทำงาน/OT/หยุด)

## บทที่ 5 · พอตเตอร์ / วีลแชร์ (scrLP)

หน้าเดียว 2 โหมด: **LP จ่ายงาน** (หัวหน้า) และ **งานพอตเตอร์ของฉัน** (พอตเตอร์)

### โหมด LP (จ่ายงาน) — เฉพาะ "แก้ไขได้"
- บนหัว: นับสด "เคสรอจ่าย n · กำลังบริการ n · รถเข็นว่าง n · ถัดไป: {พอตเตอร์}"
- **คิวพอตเตอร์** เรียงจากคนที่ทำเที่ยวน้อยสุด (คนถัดไปไฮไลต์เขียว)
- **รายการเคส standby:** `{ไฟลท์} · เกท {gate} · {ชนิดบริการ}` กด `เลือก`
- ล่าง: เลือก **พอตเตอร์ (ที่ว่าง) + รถเข็น (ที่ว่าง)** → ปุ่ม **"มอบหมาย (รอรับทราบ)"**
  - ต้องครบ เคส+พอตเตอร์+รถเข็น · กันเคสที่ปิด/ยกเลิก · กันรถเข็นที่กำลังใช้
  - สำเร็จ → เคส ASSIGNED, `pas_acknowledged=false`, จองรถเข็น, ดันคิว → "รอพอตเตอร์รับทราบ"

### โหมดพอตเตอร์ (งานของฉัน)
- เข้าโดยที่ scrSignIn เลือก **"♿ โหมดพอตเตอร์"** (ชื่อ + PIN)
- การ์ดงานของตัวเอง → ปุ่ม **"รับเคส/รับทราบ"** (บังคับก่อนเริ่ม) → ถ้ามีรถเข็นจ่ายให้แล้วจะ **เริ่มเที่ยว + ON_PROCESS** ทันที → จบงานบันทึกเวลา + COMPLETED
- พอตเตอร์ปิดงานค้างเองไม่ได้ — **ให้ LP เท่านั้น**ที่ปิด/แก้เคสค้าง
- (พอตเตอร์ไม่มี M365 → แจ้งเตือนผ่าน in-app refresh ~15–20 วิ + LINE กลุ่มทีม)

> แท็บ `♿ งานวีลแชร์` ในหน้า **งานของฉัน (scrMe)** ก็มีปุ่มรับทราบเช่นกัน

## บทที่ 6 · สำหรับผู้ดูแลระบบ (scrAdminRoles)

**เข้าได้เฉพาะ Admin** (คนอื่นเด้งกลับเมนู)

### ทำอะไรได้
1. **เปลี่ยน role ผู้ใช้** — เลือกจาก dropdown: **Admin · Editor · Viewer · Porter · Kiosk** → บันทึกทันที
2. **เปิด/ปิดผู้ใช้** (active) — ปุ่ม `ใช้งาน ✓` / `ปิดอยู่`
3. **เพิ่มผู้ใช้ M365** — กรอกอีเมล (พิมพ์เล็ก) + ชื่อ + role → "เพิ่มผู้ใช้" (ค่าเริ่ม role=Viewer, active=true)
4. **ตั้ง/รีเซ็ต PIN พนักงาน** (สำหรับคนที่ไม่มี M365 เข้า scrSignIn) — เลือกคน + PIN ≥ 4 หลัก → "บันทึก PIN"

### นโยบายสิทธิ์ (ต้องบังคับ)
- **Admin = 4 อีเมลเท่านั้น** (`hktadminpsa@` · `hktadminll@` · `sunisara.bo@` · `dutyhkt@` — `aotga.com`) — **ล็อกตายตัว** คนอื่นตั้งเป็น Admin ไม่ได้แม้แก้ตาราง
- ตำแหน่ง → role: Director/Manager/Asst.Manager/Supervisor = **Editor** · Senior/Agent/Officer = **Viewer** · Porter = **Porter** (เห็นเฉพาะวีลแชร์)
- `varPriv` (แก้ได้) = Admin หรือ Editor · `varAdmin` (หลังบ้าน) = Admin เท่านั้น
- พนักงานใหม่ sync เข้าอัตโนมัติด้วยคีย์ Emp Code (ค่าเริ่ม Viewer)

> การจำกัดการเข้าใช้ระบบ (ให้เฉพาะคนที่ได้รับสิทธิ์) ดู `48-access-restriction.md`

## แก้ปัญหาที่พบบ่อย (ทั้งผู้ใช้ + ซัพพอร์ต)

| อาการ | สาเหตุ / วิธีแก้ |
|---|---|
| scrAssign ทุกคนขึ้น **"Off"** ลงงานไม่ได้ | ยังไม่จัด roster วันนั้น → กด **"จัดอัตโนมัติ"** (ข้อ 4.4) รอ ~ไม่กี่นาที แล้วรีเฟรช |
| เข้าแล้วเมนูน้อย / แก้ไม่ได้ | เป็น **Viewer** (ดูอย่างเดียว) → ต้องการแก้ แจ้งแอดมินปรับ role เป็น Editor |
| กด "เริ่มงาน" ไม่ได้ | ยัง **ไม่กดรับทราบ** → กดรับทราบงานก่อน (บทที่ 2) |
| พอตเตอร์ไม่เห็นงานใหม่ | รอ refresh ~15–20 วิ หรือเช็ก LINE กลุ่ม · ถ้า LP เพิ่งมอบหมายให้รอสถานะ "รอรับทราบ" |
| OT ขึ้น "หลุดแผน" | มี OT จริงแต่ไม่ได้ลงใน Assign → หัวหน้าลงงาน/OT ให้ตรง หรือเช็กไฟล์ OT ว่าอัปเดตแล้ว |
| แก้กะไปแล้วหายหลังจัดใหม่ | ไม่ควรหาย — จัดใหม่ทับเฉพาะ AUTO · ถ้าหายแปลว่าแถวนั้นยังเป็น AUTO → แก้มือซ้ำ (จะกลายเป็น MANUAL) |
| เพิ่ม role Admin ให้คนใหม่ไม่ได้ | ตั้งใจ — Admin ล็อกไว้ 4 อีเมล · ให้สิทธิ์สูงสุดที่ได้คือ Editor |
| ตั้ง PIN ไม่ผ่าน | PIN ต้อง ≥ 4 หลัก และต้องเลือกคนก่อน |
| ลืม PIN / ใส่ผิดถูกล็อก 5 นาที | รอ 5 นาที · ลืมให้แอดมินรีเซ็ตใน scrAdminRoles |
| ไฟลท์ยกเลิกแล้วยังเห็นอยู่ | ตั้งใจ — เก็บเป็นประวัติ (สถานะ CANCELLED) · ถูกกรองออกจากการมอบหมายแล้ว |
| M365 เข้าได้แต่สิทธิ์ผิด | แอดมินตรวจ role ใน scrAdminRoles · role มาจากอีเมลในตาราง PAS_Users |

## สรุปสั้นสำหรับซัพพอร์ต (cheat-sheet)
1. **ปัญหาเกือบทั้งหมดของ Assign** = ยังไม่จัด roster → จัดตารางก่อน
2. **สิทธิ์** มาจากอีเมล M365 (ตาราง PAS_Users) หรือ PIN (พนักงาน=Viewer เสมอ) · Admin = 4 เมลเท่านั้น
3. **รับทราบก่อนเริ่มงาน** เป็นกติกาบังคับทั้งไฟลท์และวีลแชร์
4. **แก้มือไม่หาย** เพราะจัดใหม่ทับเฉพาะ AUTO
5. ทุกการบันทึกมี **toast ภาษาไทย** ยืนยัน — ไม่ขึ้น = ยังไม่บันทึก
